▼ Kernel Launch — CPU tells GPU to create workers
4
Kernel Launch: CPU → GPU "Start working!"
CPU issues command
scale<<1, 8>>(deviceData); // 1 block, 8 threads, pass pointer
What the GPU receives:
gridDim.x = 1→ 1 block in the grid
blockDim.x = 8→ 8 threads per block
data = 0x7f4a...→ VRAM address of the array
CPU does NOT wait here! It continues to the next line immediately (async launch). GPU starts working independently.
▼ GPU creates threads and assigns them to hardware
5
GPU Execution: 8 Threads Run the Kernel
GPU / SM / Cores
__global__ void scale(int *data) {
  int i = blockIdx.x * blockDim.x + threadIdx.x; // compute index
  int value = data[i]; // load from VRAM
  data[i] = value * 2; // compute + store
}

▼ cudaDeviceSynchronize — CPU waits for GPU to finish
6
Synchronize: CPU Waits for GPU
CPU blocks here
cudaDeviceSynchronize(); // CPU halts until ALL GPU threads complete
Without this, the CPU might try to copy results back before the GPU is done.
